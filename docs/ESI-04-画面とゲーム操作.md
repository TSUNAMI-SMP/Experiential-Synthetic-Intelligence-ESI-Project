# 画面を見せる・操作を教える・ゲームを試す（0.4.3）

## 最初の設定

1. 本体上部の開始ボタンでESIを開始し、「画面・PC操作・実演」を開く。
2. 「操作画面を広く開く」を押すと、操作用の画面だけを大きく表示できる。このタブでは標準でアバターを隠す。別のタブへ戻ると、元の表示設定に戻る。
3. 見せるモニターを選ぶ。操作するときは「マウス・キー操作」、実演を見せるときは「実演を記録」を選び、「共有を開始・設定を適用」を押す。
4. 「3秒後のウィンドウを対象にする」を押し、3秒以内にゲームや教えたいアプリへ切り替える。ゲームの中を一度クリックする。対象のウィンドウがあるモニターを自動で選ぶ。
5. ESIへ戻って対象の名前とプレビューを確認する。新しい画像が欲しいときは「画像を更新（3秒後に取得）」を押して対象アプリへ切り替える。

ゲームを操作するときは対象ウィンドウを選ぶ必要がある。PC操作・画面共有・実演の許可は起動のたびにOFFになり、会話の停止、セーブの切り替え、終了でも解除される。操作中に別のウィンドウへ切り替えると入力を停止し、キーとマウスボタンを離す。ブラウザーの別タブは同じウィンドウなので、プレイ中はタブを切り替えず、ゲームを別ウィンドウで開くと対象が分かりやすい。

**F8**または**すべて停止**で、開始の予約・画面共有・実演・操作を停止する。ゲーム自身の一時停止とは別の機能なので、停止した後のゲームの進行はゲーム側で止める。

## 画面を見る・説明を教える

「見る・説明する」で短い質問を入れ、「今の画面を見てもらう」を押す。対象ウィンドウを選んでいるときは3秒以内にそのアプリへ切り替える。読み取り中の秒数と、読み取った内容を表示する。

初回は画像AIを起動する。CPUでは1〜2分程度かかる場合がある。言語がGPUでも、画像AIは空きVRAMなどに応じてCPUになる場合がある。0.4.3では出力を短い形式に制限し、出力上限で途中までになった結果や壊れたJSONを適用せず、1回だけ短く再試行する。繰り返し失敗した場合は理由を表示し、もう一度試せる。会話の失敗とは分けて扱う。

「この説明を教える」は、入力した文章を取得画像と結び付ける。AIが推測した画像の内容と、利用者が教えた説明は区別する。曖昧なものを必ず正確に読めるわけではない。

## ゲームの操作を教える

「ゲームを教える・試す」を開く。

1. **プリセット**でslither.io、矢印キー、WASDから選び、「プリセットを読み込む」を押す。ゲームごとの設定は名前を付けて保存できる。
2. **ルールの文章**に、目的、画面の見方、操作の役割、やめる条件を書く。画像AIモードが操作を考えるときに参照する。
3. **操作表**を直す。キーは `W`、`SPACE`、`LEFT` など、同時押しは `W+SPACE` と書く。マウスボタンは `left`、`right`、`middle`。`最長 ms` は一度の入力の長さの上限で、1000 msまで。画像AIはそれより短く押すこともできる。
4. プレビュー上でゲーム部分だけをドラッグして囲む。ブラウザーのアドレス欄やタブは範囲に含めない。「画像を大きくして教える」を使うと、小さい物体も選びやすい。
5. 下記のどちらかの判断方法を選び、必要な情報を教える。
6. 「教えた内容を保存」。操作表の行を選び、「操作を1回試す（3秒後）」で対象アプリへ切り替え、キーやボタンが届くことを先に確認する。
7. 最初は5秒など短い時間で「プレイを試す（3秒後）」を押し、対象アプリへ切り替える。現在の画面から次の動きを選び直す。初回の判断・AIの準備は、プレイ時間を計り始める前に行う。

キーは英数字と `CTRL / SHIFT / ALT / ENTER / TAB / ESC / BACKSPACE / DELETE / HOME / END / LEFT / RIGHT / UP / DOWN / PAGEUP / PAGEDOWN / SPACE` に対応する。F8はESIの停止専用。操作表には、教えたいゲームの中で使うキーを登録する。

### 色の目印を追う：速い2D向け

画像の選択欄で「自分」「集める物・目標」「避ける物」「終了の目印」を選んで、その色の中央をクリックする。違う色は複数教えられる。背景や輪郭の境目を選ばず、物体の内側を選ぶ。

- 移動するキャラクターでは「自分の頭は画面の同じ位置」をOFFにし、自分の色を教える。
- カメラが自分について動くゲームでは同じ位置をONにし、自分の頭をクリックする。頭の位置を基準に目標と危険を探す。
- キー移動では操作の名前を「上・下・左・右」にする。例えば「右」のキーを `D` から `L` に変えると、右へ進む判断に `L` を使う。斜めには同時押しを使う。
- 自分や教えた目標を見失った場合、または教えた危険を避ける方向が決められない場合は止まる。色を追加したり、範囲を直して再開する。

この方式は、現在の画像で教えた色へ向かい、教えた危険を避ける処理。文章のルールを自由に理解したり、実演から未知の戦術を学ぶ処理ではない。画像AIを毎回待たずに動ける一方、同じ色の敵味方、未登録の色、隠れた物体、複雑な背景は区別できない。加速・ジャンプなどの追加操作は操作表で試せるが、この方式で自動選択するのは移動だけ。

### 画像AIでルールを考える：低速・静止画面向け

現在の画像と、保存したルール・操作表・実演の入力例を画像AIへ渡し、次の操作を選ぶ。教えていない操作は実行しない。実演は入力の例として参照し、モデルの重みを訓練するわけではない。

判断が2秒以上かかった場合、動いてしまった古い画面への操作を止める。ゲーム範囲が全く変わっていない静止画面では、新しい画像でも同じ状態と確認してから操作できる。CPUでは動きの速いゲームに間に合わない。パズルなどの静止画面や、画像AIを十分速く動かせる場合に使う。

## slither.ioで試す例

1. ブラウザーでゲームを別ウィンドウに開き、利用者がゲームを開始する。
2. そのウィンドウを対象にし、slither.ioのプリセットと「色の目印」を選ぶ。
3. ゲーム部分を囲み、「自分」を選んで頭の内側をクリックする。「自分の頭は画面の同じ位置」をONにする。
4. 「目標」で食べる粒を数色、「危険」でほかのヘビの体を数色教える。小さい粒は拡大して選ぶ。
5. 保存して、まず5秒プレイ。既知の粒に向かい、既知の危険を避けるか確認する。頭の位置・範囲・色を調整してから時間を延ばす。

標準の加速はSPACEで、操作表の1回テストに使える。色の目印モードは自動加速しない。別の操作を使うゲームでは表を直す。オンラインのslither.ioで安定して生存・上達することは未検証で、操作を教えただけでゲーム全体を習得する完成済みのゲームAIではない。色と背景を区別しやすく、失敗後にすぐやり直せる低速の2Dゲームから試すのがよい。

## 実際の操作を見せる

ゲームの設定を保存し、「実演を記録」を許可した状態で「ゲームの実演を記録（3秒後）」を押す。対象アプリへ切り替え、数秒の短い操作を見せる。キーやマウスボタンを離し、少し待ってからESIへ戻り、「記録を終了して覚える」を押す。

ゲームの実演ではキーの押下・解放と長さ、マウスの移動、左右・中央ボタンを、前後の取得画像と結び付けて保存する。画像AIモードが直近の入力例を参照する。動くゲームに古い座標をそのまま繰り返す機能とは分ける。

「一般のPC操作・実演」は、メモ入力など短い手順を記録・再現する従来の機能。ゲーム用の実演と区別して使う。一般の実演は対象の画面要素や画像の目印を探し直してから再現する。

## 保存と確認できた範囲

ゲームごとのルール・操作表・色・実演は、セーブの隣の `<セーブ名>.screen` 内へ保存する。同じ `data` とセーブを使い続ければ引き継ぐ。`games` に設定、`game_demos` に実演、`game_episodes` に試行記録がある。画面の内容・ルール・実演のキー入力は診断ファイルに含めない。

クラウドの実画面で、色から目標を追い直す2Dテスト、WASD・同時押し・マウスボタン、実演記録、許可解除後のキー解放を確認した。実Windowsのゲーム入力、RTX 5060での画像AI速度、実slither.ioの安定プレイは利用者の環境で確認する。入力の実行と、ゲームの勝敗・スコアは区別して記録し、未確認の勝利を成長の報酬にはしない。
