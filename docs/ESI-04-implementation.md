# ESI-04 実装・検証記録

状態: ESI-04（0.4.4）。環境プラグインとFabric 1.21.11のMinecraft連携を追加。0.4.3の画面・ゲーム操作、0.4.2の音声修正、0.4.1の履歴保護・口パク修正も含む。WindowsのGPU・物理音声機器・Minecraftのクライアント表示は、利用者のPCで確認する。

## 0.4.4の環境プラグインとMinecraft

人格・信念・会話・社会的欲求を保ち、仮想の部屋とMinecraftを明示的に切り替える。Minecraft連携中は旧身体・配置物・部屋の自律行動を止め、満腹度と体力を身体維持の入力に使う。未接続の時に前回の値を現在値として答えず、旧身体も勝手に進めない。

Fabric 1.21.11・Carpet 1.4.194の独立した仮想プレイヤーを使う。接続は同一PCのループバックHTTP、プレイヤーの接続コード、接続ごとの一時許可で限定する。ワールド操作はサーバースレッドで行い、移動・採掘・食事には通常のゲーム処理を使う。初参加以外は保存済みの位置・ディメンション・所持品・身体を復元する。

初期知識は基本知識と操作方法に限定。隠れた鉱石やシードを与えず、近くで見える対象と自分の所持品から、構造化出力の列挙値で次の一操作を選ぶ。CPU推論中も観察を別スレッドで継続し、実行前に最新の観察で対象・スロットを確認する。古い接続・セーブ切り替え・新しい会話で取り消した結果は実行しない。

行動の理由・実際の結果・観察IDを保存し、最近の結果と教わった知識を次の判断へ渡す。行動結果の記録は同じ操作IDで重複させない。質問には普通の会話で答えられ、同じ観察のまま同じ質問を繰り返さない。未確認の使用操作を成功した経験として加点しない。基盤モデルの重みの追加訓練は行わない。

導入と範囲は [Minecraft連携](ESI-04-Minecraft連携.md)、通信・再ビルド・テストは [MODのREADME](../plugins/minecraft/README.md) を参照する。

## 0.4.3の画面・ゲーム操作

- 提供ログでは画像AIはCPUで正常に起動していたが、最初の出力が768トークン上限へ達していた。切れたJSONを結果として扱わず、入力用の短いスキーマと1回の再試行を追加。以前の長い観察を含む保存形式は変更しない。
- 汎用の状態更新で `phase=failed` が具体的な例外を上書きしていたため修正。画面・操作コマンドの失敗は会話の失敗と分け、再試行時に解除する。取り消された処理の遅い結果を反映せず、表示を待機へ戻す。
- 対象はモニターと、選んだウィンドウのhandle・pid・applicationで拘束する。ゲーム中はUI Automationの遅い列挙を省いて実画像を取得する。描画範囲の座標変換、別アプリへの切り替え、古い画像への入力を検査する。ゲームの動く画面には一般PC操作の固定画像アンカーを流用しない。
- キー・マウスの押下と解放を実装。入力中も約20 msごとに許可・前面ウィンドウ・F8を確認し、キャンセルや例外時はESIが押した入力を解放する。F8は共有開始前の予約も取り消す。一般PC操作の一度だけの入力・重複防止・結果確認は維持する。
- ゲーム設定はセーブごとのJSONへ保存。色の目印モードは登録した色の画像処理による追跡と回避、画像AIモードは現在の画像・利用者のルール・操作表・実演の入力例からの選択。LLM重みの追加学習や汎用ゲーム攻略の達成は主張しない。画像AIでの判断が遅い場合は、ゲーム範囲が変化していない静止画面だけ新しい画像で再確認する。
- ゲーム試行の入力・根拠画像・停止理由を保存し、勝敗を未確認として扱う。ゲームの操作を送れたことだけで成功報酬を付けない。診断には画像・実演内容を含めない。

## 0.4.2の音声処理と検証

利用者の画像は、返答文が表示された後に音声が出ない／途中で止まる状態だった。元のWindowsのエラー本文はまだ取得していない。画像と同じ3入力は修正前もクラウドのCPU・仮想音声出力では通ったため、そのPCの個別原因を確定したという記録ではない。

- 出力機器を開く際のPortAudioエラーに対し、音声をまだ渡していない場合だけ、対応を確認した標準サンプルレート・チャンネルで再試行する。機器に合わせたバッファーとhigh latencyを使い、すでに音声を渡した後は自動で繰り返さない。
- 一時的な音声合成の接続・一部のHTTPエラーは1回だけ再試行。GPUメモリ不足が明示され、ASRが自動GPU配置である場合だけ、そのモデルをロック内で解放し、次の認識をCPUにして音声を再試行する。GPU必須設定は守る。
- 音声失敗でLLMの文章生成をキャンセルしない。音声ファイルと失敗段階を残し、「返答をもう一度読み上げる」では生成済み音声を再利用できる。新たな会話入力や部屋・PC操作として扱わない。
- 警告は会話欄の下だけでなく上部にも表示。返答ごとの音声生成・再生の失敗詳細を会話欄に表示し、音声合成と聞き取り・言語処理を区別する。APIの失敗本文はローカルで閲覧できるが、診断には本文やURLクエリーを入れず、段階・エラー種別・HTTPコード等のみを渡す。

| 確認 | 結果 |
| --- | --- |
| 自動回帰 | **338件成功、任意1件スキップ**。対応形式への再試行、途中再生を自動で繰り返さないこと、音声失敗後の文章の保持、生成・再生の区別、音声再試行で物体を重複配置しないこと、GPU必須設定とCPUメモリ不足との区別、診断の本文除外を含む。 |
| 実音声の障害復帰 | 実際の凛音エルの合成と、実際のPortAudioの仮想ALSA出力を接続。「こんにちは」「聴いてるよ」「あなたは自分が誰だかわかっていますか？」を処理。2番目だけ機器を開けないエラーを注入し、返答とWAVを保持。出力復帰後、同じWAVを再合成せず再生し、3番目も再生した。実Windows・GPU・物理スピーカーの試験ではない。 |

履歴の復旧は今回の必須範囲から外し、0.4.1の保持機能を維持した。

## 0.4.1の修正と検証

- 口を開く側のキーだけ描画順が801となり、顔を補うレイヤーに隠れていた。開閉の両キーを803にそろえてCubismから再出力し、中間値も確認した。メッシュの変形だけでなく、実アプリの音量メーターと表示上の口の画素を検査する回帰ケースを追加した。開口後、無音時には元の閉じた口へ画素単位で復帰する。
- 会話タブの直近12件より前の記録を読む画面と、元セーブを探す画面を追加した。旧絶対パスがなくなった場合は同じ `data` 以下の移動先を確認し、新しい起動設定には相対パスを使う。ESI-02/03のコピー移行を選べる。現在のESI-04や別のキャラクターのセーブへ自動で上書き・結合しない。
- 従来の動作ログの容量整理で会話の記録も削られる経路があるため、会話を専用の `esi04_conversations` テーブルに保存する。初回の更新時は、容量整理より前に残っているイベントと現在の会話状態から退避する。以前の版ですでに消えた記録を復元できる保証はなく、元セーブやアーカイブも確認する。
- 音声認識の遅延実行で発生する計算形式のValueErrorと、失敗したCUDAの後片付けも扱う。自動設定のメモリ不足ではfloat32を試して負荷を増やさず、同じ録音をCPUで再処理する。GPU必須設定は守る。成功した認識でその認識エラーを解除し、失敗・待機・入力待ち超過の件数を表示する。PortAudioの一時的な出力バッファ不足だけで発声を中断しない。

## 実装する内容

1. 会話の意図・提案・自己状態・欲求・興味・質問への回答を区別し、単語だけで身体報告へ分岐しない。
2. 直前の質問と自然な音声・文字の回答を対応付ける。曖昧なら確認し、沈黙は未観測として保留する。ボタン操作を必須としない。
3. 固定周期の質問を廃し、欲求・関心・出来事・相手の状態・競合する行動から発話を選ぶ。同じ問いを無根拠に反復しない。
4. お菓子・家具・パソコン等の物体を位置・個数・状態付きで配置・移動・撤去。自然文と画面の双方に対応する。
5. ESIが見る・近づく・調べる・使う・食べる・休む行動を選び、実際の状態変化から記憶・好みを更新する。
6. 会話のない間に経験を整理し、矛盾・未解決の疑問・計画・調査・操作技能の再検討を進める。生成した推測を観測済みの事実や正解にしない。
7. 内部状態と意図から表情・視線・簡単なポーズを選ぶ。必要なCubismの作画・リギングを含める。カーソル追従は任意。
8. 2Dアバターにクリックできる吹き出しを付け、関心・検討候補・選択理由・結果の短い要約を表示する。
9. 画面閲覧を許可した際に選択画面を観察し、視覚モデルと画面の文字・要素を利用して説明と対応付ける。
10. PC操作を許可したセッションでマウス・キーボード操作を行い、操作前後の実画面から結果を確認する。
11. 利用者の実演と説明を時系列で記録し、画面条件・対象・操作・結果を技能として覚え、似た状況で再利用・失敗修正する。
12. PC操作許可時にアバターの位置を把握し、注意の対象や操作対象を踏まえて自分で移動する。

## 保存と検証

- ESI-03から読み取り専用コピーで移行し、元セーブ・履歴・キャラクター・知識を保持する。
- 外部操作の権限は再起動後に自動復活させず、途中だった操作も自動再実行しない。
- 画面・操作実演は選択・許可された範囲をローカルで扱い、診断へ画面や本文を混入させない。
- 掲載された利用者の会話ログを連続した回帰ケースにする。
- 模擬結果だけで完成としない。実言語・視覚モデル、実スクリーン取得と操作、ネイティブ描画とCubism再出力、保存・復旧・既存版互換を検証する。
- 実機Windows・GPU・物理音声とクラウドでの検証は区別する。
- 基礎モデルの重みの自動訓練は今回の範囲に含めず、経験・記憶・技能・判断の変化を測る。
