# ESI-04 の導入と確認

## 0.4.4：Minecraftプラグイン

ESIを終了し、更新版ZIPの内側のファイル・フォルダーを、今まで使っていたESIフォルダーへコピーする。`data`、`models`、仮想環境、AivisSpeechを保持する。`ESI-04を起動.cmd` を開き、上部の **ESI-04 0.4.4** を確認する。既存のAIデータの再ダウンロードは不要。

Minecraft連携を使う場合は、[Fabric 1.21.11の導入手順](ESI-04-Minecraft連携.md)に従い、Fabric API・Carpet・同梱のESI Bridge JARをMinecraft側へ追加する。ESIの「プラグイン・Minecraft」タブから接続し、自律活動を開始する。Minecraftを使わない場合は従来どおり起動できる。

## 0.4.3：画面認識とゲーム操作

ESIを終了し、更新版ZIPの内側のファイル・フォルダーを、今まで使っていたESIフォルダーへコピーする。`data`、`models`、仮想環境、AivisSpeechは保持し、空の別フォルダーで新しいセーブを作らない。`ESI-04を起動.cmd` を実行し、上部の **ESI-04 0.4.3** を確認する。この更新によるAIデータの再ダウンロードは不要。

画面認識の途中で切れた出力を短い形式で再試行し、具体的な原因が `phase : failed` で消えないようにした。操作タブは、対象ウィンドウ・画像プレビュー・観察・ゲーム・一般の実演に整理した。「操作画面を広く開く」で大きく表示できる。

キーの長押し・同時押し・マウスボタンを教え、画面を見ながら簡単な2Dゲームを試せる。**F8**で停止し、キーとボタンを離す。初期設定・slither.ioの教え方・判断方式の違いは[画面とゲーム操作の手順](ESI-04-画面とゲーム操作.md)を参照する。

## 0.4.2：返答文の後に音声が止まる場合の対策

ESIを終了し、修正版の内側のファイル・フォルダーを今までのESIフォルダーへコピーして、`ESI-04を起動.cmd` を実行する。上部に **ESI-04 0.4.2** と表示されることを確認する。AIデータの再ダウンロードは不要。

音声機器を開く際に失敗した場合、再生データをまだ渡していない時に限り、その機器の標準サンプルレートと対応チャンネルで再試行する。バッファーは機器に適したサイズと余裕のある遅延を使う。すでに途中まで再生した音声を自動で最初から繰り返さない。

音声の生成・スピーカーへの出力が失敗しても、返答文を作る処理は続ける。失敗した段階と詳細を上部の警告直下、および会話欄の返答の下に表示する。AivisSpeechの一時的な接続失敗・429/502/503/504は1回だけ再試行する。音声合成がGPUメモリ不足を明示した場合は、聞き取りが自動設定の時だけASRのGPU使用を解放してCPUへ切り替え、音声生成を再試行する。GPU必須設定は守り、指定の音声モデルも変更しない。

「返答をもう一度読み上げる」で、表示済みの返答を最初から読み上げられる。生成済みの音声ファイルがあれば再利用し、質問の再送信・返答の作り直し・部屋やPCの操作は行わない。出力機器を変える場合は、いったん停止し、実際に使うスピーカー・ヘッドホンを選んで「音のテスト」を行い、開始してから読み上げを再試行する。

GPU表示は言語モデルと聞き取りの確認であり、音声合成やスピーカーの成功を示す表示ではない。まだ失敗する場合は、今回から会話欄に表示する詳細を確認する。利用者のWindowsで発生した元のエラー本文は未取得のため、その個別原因が解消したかは実機での再確認が必要。

## 0.4.1へ更新する・会話履歴を確認する

ESIを終了し、ZIPの内側のファイルを今までのESIフォルダーへ上書きコピーして、`ESI-04を起動.cmd` を実行する。`data`、`models`、既存の仮想環境、AivisSpeechは残す。新しい空のフォルダーで起動すると、元フォルダーにあるセーブは読み込まれない。

会話画面は直近12件の表示であり、それより前の記録は「会話履歴・セーブ」タブから読める。「さらに前の会話を表示」で、データベースに残っている記録をさかのぼれる。モデルへ渡す短い会話文脈の上限は変更しない。

0.4.1以降の会話は、動作ログの容量整理とは別に保持する。更新時には残っている記録を退避するが、以前の版で既に削除された記録は元セーブやアーカイブからの確認が必要になる。

以前の会話がない場合は、このタブの「以前のセーブ・会話履歴を探す」を押す。現在の保存先と、同じESIフォルダー内にあるセーブの版・キャラクター名・会話件数を確認し、以前使っていたものを選ぶ。ESI-02/03は新しいESI-04ファイルへコピーし、元ファイルと現在のESI-04は残す。別々のキャラクターの記憶は自動で混ぜない。元のセーブが別のフォルダーにある場合は「セーブを開く」で `data\esi03\session.sqlite3` など実際の保存先を指定する。

0.4.1では、口を開く設定の描画順を修正し、音量に応じた口パクを復元した。音声出力の一時的なバッファ不足だけで発声全体を中断しない。音声認識の自動設定では、CUDAの計算形式の失敗やメモリ不足時に同じ録音をCPUで再処理する。GPUを必須に指定した場合はCPUへ切り替えず、失敗を表示する。

「聞き取り」の認識失敗件数・待機件数・入力待ち超過件数と、警告下のエラー文を確認できる。正常に認識できたら、その認識エラーの警告を解除する。問題が続く場合は、表示されたエラー文か「診断を保存」の結果を確認する。Windowsのマイク・GPUで今回の症状がすべて解消したかは実機での確認が必要になる。

## ESI-03から更新する

1. ESI-03の画面を閉じる。
2. [GitHubのESI-04 ZIP](https://github.com/TSUNAMI-SMP/Experiential-Synthetic-Intelligence-ESI-Project/archive/refs/heads/esi-04-development.zip)をダウンロードして展開する。
3. 展開した内側のファイル・フォルダーを、今までのESIフォルダーへコピーして更新する。`data`、`models`、`.venv-esi02`、`.venv-esi03`、AivisSpeechのファイルは残す。ZIPから導入したフォルダーでは `git pull` は使わない。
4. `ESI-04を起動.cmd` をダブルクリックする。初回はESI-03のセーブをコピーして移行する。ESI-03がなければESI-02からコピーする。会話・知識・性格・欲求・履歴と元セーブを保持する。
5. 画面認識用のAIデータを約1.55 GB追加で準備する。既存の会話・聞き取り・音声データは使い続ける。ダウンロードが止まった場合は同じ起動を再実行する。

通常のセーブは `data\esi04\session.sqlite3`、元データの一貫したアーカイブは `session.esi03-original.sqlite3`。別の場所にあるESI-03のセーブは「セーブを選ぶ」で指定し、新しいESI-04用のコピー先を選べる。途中だったPC操作は移行後に再実行しない。

初めて導入する場合はPython 3.12の64ビット版とAivisSpeechを導入し、`ESI-04の初回準備・更新.cmd`、`ESI-04を起動.cmd` の順に実行する。AIデータがなければ起動画面の「AIデータの準備」を押す。ライブラリの読み込みで止まる場合も「初回準備・更新」を実行する。

## 会話と自発的な質問

ESIの質問には、普通にマイクで答えるか会話欄へ入力すればよい。回答ボタンは必須ではない。質問と関連する返答を対応付け、曖昧なら「さっきの質問への答えで合っている？」と確認する。返答がない場合や別の話題へ移った場合は未観測として保留し、拒否や嫌悪として学習しない。長く保留された質問へ無関係な「はい」を結び付けない。

「仮想の部屋の居心地はどう？」「何か欲しいものはある？」「おやつに興味ある？」は、それぞれ居心地・欲求・興味として扱う。「仮想」という単語だけで体力報告へ切り替えない。数値を知りたい場合は「活動エネルギーと疲労を数値で教えて」と頼む。

自発的な質問に固定の最短間隔は設けない。関心・欲求・相手の在席や忙しさ・休息や探索との比較で選ぶ。同じ証拠のまま同じ質問を反復しない。「今は忙しい」「後で」で保留でき、「戻ったよ」などで会話へ戻れる。自発的な発話そのものは「性格・欲求・成長・探索」の設定で停止できる。

## 部屋に物を置いて観察する

「仮想の部屋・身体」の一覧で種類・個数・座標・机の上／床を選び、「置く」を押す。一覧の物を選んで「移動」「取り除く」「近くへ行く」「調べる」「食べる」「使う」を操作できる。

会話でも、例えば次のように頼める。

- 「机の上におやつを置いて」
- 「ボールを置いて」
- 「おやつを右に動かして」
- 「おやつを床に移動して」
- 「ボールを取り除いて」

「例えばおやつを持ってくることができるよ」という説明だけでは配置しない。同じ名前の物が複数あるときは一覧から選ぶ。家具の重なり、壁や天井からのはみ出し、身体と重なる配置、届かない高さは反映せず理由を表示する。家具の周りを通る経路を選び、食べたおやつの個数と活動エネルギーは実際に変わる。

机・本・仮想のパソコン等を置くことと、実際のPCやインターネットへ接続することは別の設定。書かれていない本の内容や、使っていない実機の結果を知識として作らない。

## 画面を見せる・教える

1. 本体の「画面・PC操作・実演」を開く。下の操作が見えない場合はタブ内をスクロールする。
2. 共有する画面を選び、「画面の観察を許可」にチェックして「設定を適用」を押す。
3. 会話で「この画面に何が見える？」「このボタンは何？」と尋ねる。または説明欄に質問を書いて「今の画面を見てもらう」を押す。
4. 「このボタンは下書きを保存するボタンです」のように普通に説明すると、その時の画面と発言を対応付ける。説明欄の「画面についての説明を教える」も使える。

画像の読み取りは推定であり、利用者からの説明と区別して保存する。「さっき画面について教えたことを覚えている？」と尋ねると、教えた発言を参照できる。会話がない間も、共有された画面の変化と関心を踏まえて観察するか選ぶ。

動画も表示されている画像を順次観察する。全フレームの追跡や動画の音声の自動理解は含まない。場面を止めて説明すると対応付けやすい。読み取りに時間がかかるPCでは、結果を受け取る間に場面が変わることがある。

## PC操作と実演からの学習

画面の観察に加えて「選択画面内でマウス・キーボード操作を許可」を選ぶと、見えている対象へクリック・入力・キー・スクロールを実行できる。例えば「入力欄に hello ESI と入力して」と頼む。現在の対象を確認できない場合や、アプリ・入力先が途中で変わった場合は止めて再観察する。

操作の仕方を見せるには、次の順に進める。

1. 「実演の記録を許可」を選んで設定を適用する。
2. 実演の名前と目的を入力し、「実演の記録を開始」を押す。
3. 3秒以内に教えたいアプリへ切り替える。アプリでクリック・入力などをゆっくり行い、各操作の前後の画面が取れるようにする。
4. 本体へ戻り「記録を終了して覚える」を押す。
5. 対象アプリを開いた状態で一覧の「選んだ実演を再現する」を使う。会話でも、例えば覚えた名前が「メモを書く」なら「メモを書くを再現して」と頼める。

対象は画面要素の識別情報や、実際に切り取った画像の目印で探し直す。曖昧な目印、違うアプリ、読み取れなかった操作を含む実演は途中の入力を進めない。失敗の記録を確認し、対象の操作をゆっくり見せ直せる。文字入力の実演では、その時の入力内容を再現する。任意のアプリの未知の操作を必ず習得・実行できる保証はない。

「この実演を、自分で選んで練習してよい」を選んだ実演は、PC操作の許可中にESI自身が練習を選べる。実演ごとに許可を変えられ、「選んだ実演を削除する」で保存した技能を削除できる。

「すべて停止」は画面・操作・実演を解除する。「PCの操作を止めて」と普通に話して停止することもできる。本体の会話停止、セーブ切り替え、終了でも解除し、次の起動に許可を持ち越さない。操作後の画像の変化だけでは達成扱いにせず、入力欄等の具体的な結果を確認できた場合にのみ成功の経験を付ける。確認できなかった場合は、その旨を活動の記録に残す。

画面の画像・操作・実演はセーブの隣の `<セーブ名>.screen` フォルダーへ保存する。通常の保存先は `data\esi04\session.screen`。同じフォルダーの別セーブとも混ぜない。通常画像は設定の容量内で古いものから整理し、実演に必要な画像は残す。診断ファイルには画面・入力文・会話や技能の内容を含めない。

## 表情・動き・吹き出し

「性格・欲求・成長・探索」で、自主的な体の動き、カーソル追従、活動の吹き出しを切り替えられる。標準は自主的な動きがON、カーソル追従がOFF。喜び・戸惑い・疲れなどと、尋ねる・考える・調べる・休む意図に合わせて眉・口・頭・両腕を動かす。腕は穏やかな簡易ポーズで、独立した指の関節や大きく手を上げる動作はない。

吹き出しをクリックすると、今の活動、関心、比べた行動、選択の短い理由、確かめた結果を見る。観察・推測・予定を区別して表示する。

「操作中にアバターが自分で位置を変える」を許可すると、実際の操作対象の近くで、対象を隠さない位置へ動く。利用者が手で動かした位置は、次に新しい対象へ注意が変わるまで尊重する。

## GPU・動作確認

会話と聞き取りの設定は「GPU設定・計測」にある。画面認識は必要な時に別の小型モデルを起動し、空きVRAMを見て配置する。自動設定でGPUの起動や画像の計算に失敗した場合は、理由とログを残してCPUで再試行する。会話のソフトを画面認識のソフトで上書きしない。

RTX 5060の8 GBでは、会話・聞き取り・画面認識・描画がVRAMを分け合う。GPUへ読み込めたことと、実際の推論に成功したことを区別する。重みはQ4_K_Mであり、NVFP4を用いたBlackwell専用の最高速度を測定した版ではない。

更新後は、次を確認する。

- 会話・マイク・スピーカー・声と口の同期、言語と聞き取りのGPU表示。
- 通常の顔、まばたき後の復帰、眉・口・簡単なポーズ、首・襟・髪の重なり。
- 質問への普通の返答、身体報告への誤分岐がないこと、忙しい時の保留。
- おやつ等の配置・移動・消費と、再起動後の記憶。
- 共有画面の読み取り、実演の記録・再現、許可解除で操作と自主移動が止まること。

問題があれば「診断を保存」または `ESI-04の診断を保存.cmd` を使う。記録は通常 `data\esi04\diagnostics`、起動記録は `data\esi04\logs` にある。クラウドで確認できた範囲と、利用者のWindows・GPU・物理機器で確認する範囲は[実装・検証記録](ESI-04-implementation.md)に記載する。
