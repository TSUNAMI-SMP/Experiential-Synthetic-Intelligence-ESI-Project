# ESI-01 検証記録

検証日: 2026-10-13（日本時間）。Linux x86_64 / Debian 13 / Python 3.12.14、CPU 動作で確認しました。

0.2.1の修正では、起動時のEngine 1.2.0限定条件を取り除きました。基本・回帰61件が成功しました（実モデル統合3件はこの修正では再実行していません）。Engine 1.1.0／1.2.0のAPI応答を代替した起動テストで、接続と凛音エルの照合まで進むことを確認しました。Engine 1.1.0の実バイナリやユーザーのWindowsでの音声合成を確認したものではありません。以下の63件の実行記録と `test-results.json` は0.2.0の検証です。

0.2.0 の自動テストは基本・回帰60件と実モデル統合3件で、**63件すべて成功、失敗・スキップ0件**でした。最終実行の件数・ソースハッシュは `test-results.json`、前版53件の結果は `test-results-v0.1.1.json` に記録しています。統合テストの音声入力は実 AivisSpeech / 凛音エルが生成した日本語 WAV であり、ユーザーのマイク音声ではありません。48kHz stereo に変換した実合成音声を、マイク処理ワーカー・VAD・ASR に通す経路も確認しています。未導入・誤った版・別話者・別スタイルで別の声へ切り替わらないことも回帰テストで確認しています。

最前面のアバターを本体とは別のトップレベルウィンドウとして作り、本体最小化中の開始・停止／マイク操作、位置と大きさの保存、表示の操作で学習状態が変わらないことを確認しました。セーブを開く操作では、旧セッションを保存・停止し、新セッションの保存設定・学習・個体IDを復元し、壊れたファイルを選んだ場合に現在のセッションと対象ファイルを保持することを確認しています。

Live2Dの実描画は、公式 `Live2D/CubismNativeSamples` のHaru（revision `a3a64f6cb327aafce380949e0f54fe51c4d773d9`）を使い、Qt xcb / Xvfb / ソフトウェアOpenGLで検証しました。実際のMOC3とテクスチャを読み込み、42パラメータを確認し、フレームの変化、発声中の口の開き、立ち絵への切替、モデル再読み込み、正常終了を検証しました。Pythonラッパーは `live2d-py` 1.0.0、実行時のCubism Core表示は6.0.1です。**Haruは凛音エルではなく、この検証は凛音エルのLive2Dモデルの完成を意味しません。** サンプルは配布物に含めません。

起動処理は、既存サービスの再利用、Qwenモデルの一致、指定版の凛音エル、自分で起動したllamaだけの終了、起動中止を回帰テストで確認しました。実際のローカルQwen/AivisSpeechへの接続確認から、本体の画面を開き正常終了する流れもLinuxで実行しました。Windows用の追加3パッケージのホイールを公式PyPIの固定ハッシュで取得でき、配布用Pythonホイールに透過画像と13個のSVGアイコンが含まれることを確認しました。WindowsのCMD／PowerShellの実行とWindows上の透過・最前面表示は実機で未確認です。単体Windows EXEは作成していません。

音声機器の選択、48kHz stereo でしか開けない機器への入出力、16kHz mono への変換、聞き取り前の音量、認識処理中の表示、切断、故障と待機の区別、機器番号変更・未接続時の扱い、取り外された機器の終了処理、古い取得スレッドの状態を新しいマイクに適用しないこと、選択した出力先への再生を回帰テストに追加しました。機器そのものは代替オブジェクトで確認し、物理機器の成功とは扱いません。GUI の開始操作でマイクを開始すること、機器設定が実験設定の指紋を変えないこと、無音時の判断が直前の入力に対する判断表示を隠さないことも確認しました。

環境の再インストール、復元後の起動、所有サービスだけの停止・再起動を実行しました。依存環境の機能チェックも7件成功し、凛音エルの実合成・日本語ASR・QwenのJSON応答を確認しています。音声導入コマンドの繰り返しは既存モデルを照合し、重複登録しません。再利用用の `install_script` と `start_skill` は環境設定の下書きに保存済みです。

状態更新を伴う常駐処理の統合試験では、未解決度が高い試験状態を指定して確認発声の価値を高め、強制選択せずに数値評価で発声が選ばれ、その WAV が保存されることを確認しています。通常のあらゆる入力に返答する保証ではありません。

Qt は offscreen の描画、開始前の操作・共有項目と候補の表示を確認しました。録音取得の物理デバイスがクラウドにはないため、マイク取得はキュー境界・コールバック経路・ストリーミング VAD の検証までです。実デバイスの取得・再生は未実行です。

同梱の凛音エルは表示用透過PNGです。部品表は生成処理で作ったパーツ分けの下書きで、制作済みPSD/CMO3/MOC3ではありません。Cubism EditorはLinux環境では利用できず、モデル制作・書き出しは残っています。モデルができた後の導入と制作引き継ぎは[アバターの説明](アバターと簡単起動.md)に記載しています。

## 模擬課題の結果

任意の数値刺激から、選んだ行動の証拠取得量を予測する小さい線形課題です。訓練80試行/条件、種1、訓練刺激 -1/+1、留保刺激は異なる6つの値です。実際の試験記録は `comparison-example.json`、再実行は `esi compare --output <新しいディレクトリ> --trials 80` です。

| 条件 | 初期留保 MSE | 訓練後留保 MSE | 測定経路での候補選択正答率 |
| --- | --- | --- | --- |
| 学習あり | 0.130100 | 0.00005022 | 0.5 → 1.0 |
| 学習停止 | 0.130100 | 0.130100 | 0.5 → 0.5 |

評価時はモデル・経験をライブ実験に書き戻さず、数値課題の正解は LLM の採点から作りません。学習停止条件の全パラメータが維持されることと、学習によって同じ開始状態で行動選択が変わることは別の回帰テストでも確認しました。

この小さい課題は実装の学習機構の確認です。自由な音声会話での汎用的な経験学習、知能の人間比較、意識の存在の測定ではありません。

## 残る確認

Windows 導入ログで見つかった colorama の不足を修正しました。Windows / Python 3.12 向けの依存関係の解決で、50パッケージすべてがロックの固定版に一致し、追加の未固定依存がないことを確認しました。colorama は Windows のみの条件付きです。前述の38件は本体の既存試験記録で、この修正後の Windows 実機インストール完了を示すものではありません。

Windows、RTX 5060/CUDA、VRAM 予算、物理マイク・ヘッドホン・割り込み、反響、実GUI操作、Ryzen 7 5700Xでの遅延、長時間実行の負荷はこのクラウドでは確認していません。[Windows 手順](windows.md)に沿った実機確認が必要です。処理待ちが長い場合も数値状態は進みますが、3〜8秒の設計目標を達成したとはしていません。

再利用設定の保存と環境の公開は別の操作です。ESI-01 のコードを含む公開後の新規タスクへの復元はまだ確認していません。
