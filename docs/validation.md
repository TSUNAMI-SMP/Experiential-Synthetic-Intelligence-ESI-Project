# ESI-01 検証記録

検証日: 2026-10-13（日本時間）。Linux x86_64 / Debian 13 / Python 3.12.14、CPU 動作で確認しました。

## 実装と検証の対応

| 範囲 | 確認した内容 |
| --- | --- |
| M0 | 実時間差による状態減衰、候補評価と選択、慣れ、共有容量、観測/管理操作の分離、SQLite 保存・再開、クラッシュ後の記録再適用、RNG・モデルの保持、処理再生 |
| M1 | 録音ファイルの Silero ONNX VAD、faster-whisper CPU int8、多言語モデルでの日本語認識、音量/F0系列、欠損、取得キューの上限、観察GUIの描画 |
| M2 | 実 Qwen3-4Bによる構造化意味推定と発声文章、参照ID検証、実 AivisSpeech / 凛音エル 合成、数値選択から発声完了までの常駐処理、生成音声の入力種別分離、古い結果/故障の扱い |
| M3 | 選択した行動の観測済み成分だけを更新、未知/想像を教師にしない、学習停止、訂正の重複排除、留保課題、状態を固定した選択の変化、評価コピーと実験分岐 |

自動テストは基本・回帰36件と実モデル統合2件です。最終実行の件数・失敗・スキップ・ソースハッシュは `test-results.json` に記録しています。統合テストの音声入力は実 AivisSpeech / 凛音エルが生成した日本語 WAV であり、ユーザーのマイク音声ではありません。未導入・誤った版・別話者・別スタイルで別の声へ切り替わらないことも回帰テストで確認しています。

環境の再インストール、復元後の起動、所有サービスだけの停止・再起動を実行しました。依存環境の機能チェックも7件成功し、凛音エルの実合成・日本語ASR・QwenのJSON応答を確認しています。音声導入コマンドの繰り返しは既存モデルを照合し、重複登録しません。再利用用の `install_script` と `start_skill` は環境設定の下書きに保存済みです。

状態更新を伴う常駐処理の統合試験では、未解決度が高い試験状態を指定して確認発声の価値を高め、強制選択せずに数値評価で発声が選ばれ、その WAV が保存されることを確認しています。通常のあらゆる入力に返答する保証ではありません。

Qt は offscreen の描画、開始前の操作・共有項目と候補の表示を確認しました。録音取得の物理デバイスがクラウドにはないため、マイク取得はキュー境界・コールバック経路・ストリーミング VAD の検証までです。実デバイスの取得・再生は未実行です。

## 模擬課題の結果

任意の数値刺激から、選んだ行動の証拠取得量を予測する小さい線形課題です。訓練80試行/条件、種1、訓練刺激 -1/+1、留保刺激は異なる6つの値です。実際の試験記録は `comparison-example.json`、再実行は `esi compare --output <新しいディレクトリ> --trials 80` です。

| 条件 | 初期留保 MSE | 訓練後留保 MSE | 測定経路での候補選択正答率 |
| --- | --- | --- | --- |
| 学習あり | 0.130100 | 0.00005022 | 0.5 → 1.0 |
| 学習停止 | 0.130100 | 0.130100 | 0.5 → 0.5 |

評価時はモデル・経験をライブ実験に書き戻さず、数値課題の正解は LLM の採点から作りません。学習停止条件の全パラメータが維持されることと、学習によって同じ開始状態で行動選択が変わることは別の回帰テストでも確認しました。

この小さい課題は実装の学習機構の確認です。自由な音声会話での汎用的な経験学習、知能の人間比較、意識の存在の測定ではありません。

## 残る確認

Windows 導入ログで見つかった colorama の不足を修正しました。Windows / Python 3.12 向けの依存関係の解決で、50パッケージすべてがロックの固定版に一致し、追加の未固定依存がないことを確認しました。colorama は Windows のみの条件付きです。前述の38件は本体の既存試験記録で、この修正後の Windows 実機インストール完了を示すものではありません。

Windows、RTX 5060/CUDA、VRAM 予算、物理マイク・ヘッドホン・割り込み、反響、実GUI操作、Ryzen 7 5700Xでの遅延、長時間実行の負荷はこのクラウドでは確認していません。[Windows 手順](windows.md)に沿った実機確認が必要です。処理待ちが長い場合も数値状態は進みますが、3〜8秒の設計目標を達成したとはしていません。

再利用設定の保存と環境の公開は別の操作です。ESI-01 のコードを含む公開後の新規タスクへの復元はまだ確認していません。
