# ESI-02 実機報告への修正（2026-10-15）

Windowsで報告されたGPU判定・聞き取り・未学習の知識の返答、および凛音エルの顔と髪の表示を修正した。RTX 5060上の推論と実マイクの再確認は、更新後の実機で行う。

## GPUの判定と復旧

提供されたllamaの起動ログはverbosity 3で、GPUへ移した層数が含まれていなかった。同じ指定版で、verbosity 4ならCPU起動時の `offloaded 0/37 layers to GPU` が出ることを確認した。ログ不足だけをGPU失敗と判定する場合があったため、起動時に層数を記録し、読み込み確認後に短い実推論も行う。検証用の推論は発声せず、会話・記憶に保存しない。

聞き取りの `CUBLAS_STATUS_NOT_SUPPORTED` はモデルの読み込み後、実際の計算時に発生していた。自動設定ではfloat16で実計算が失敗した場合、対応しているfloat32・int8_float16を順に試し、それでも失敗した場合にCPUへ戻す。失敗したモデルは解放してから次を試す。CUDAの明示指定では失敗を表示する。GPUの列挙やモデルの読み込みだけでは「GPUで計算確認済み」にしない。

診断には言語のGPU層数・実推論の確認、ASRの試行機器・計算形式・結果、Windowsで実際にロード済みのCUDA DLLを追加した。起動ログからは読み込み・配置・エラーの行だけを抽出し、会話本文は診断へ入れない。提供されたログからVRAM不足やドライバー不良を確定したわけではない。

## 聞き取りと会話

- 日本語の音声認識はbeam size 5とし、以前の文を次の聞き取りへ引き継がない。凛音エル・ESIを認識のヒントにする。無音判定は録音側のVADで行う。
- 全区間の認識が弱い場合は、聞こえた文を示して確認する。その文は確認前に知識や本人の記憶へ登録しない。「はい」「合っています」などで確認した内容を登録する。音響指標は正確な誤字率ではなく、確信の高い誤認識まで完全に検出できるわけではない。
- 本人の記憶と、教わった外界の知識を別に保存する。記憶画面で対象を選び、追加・訂正・削除できる。
- 未学習の地域・人物・雑学は、Qwenの事前学習の知識から説明しない。「まだ知りません」「教えてもらえますか」と返す。質問しただけの内容やAI自身の回答を教えられた事実にしない。
- 誤った教えも、本人から教わった内容として保持する。対象と訂正後の内容を明示して教えると反映を確認しやすい。例えば「ルーメリアは月の都市です」と教えるとその内容を覚え、「月ではなく海の都市です」と訂正すると新しい内容を使う。訂正前の会話や遅れて届いた抽出結果で旧内容に戻さない。
- 出力する返答は保存済みの根拠IDを検査してから画面と音声へ送る。無関係な記憶や存在しないIDで知っていることにしない。語尾に必ず「何かお手伝いできますか」を付ける処理は使わない。利用者や第三者の状態をAI自身の仮想の状態へ取り違えない。

**言語モデルの重みから知識を削除したり、会話で再訓練したりする更新ではない。** 今回は回答に使える根拠を制限する方式であり、挨拶・確認・記憶の説明などには定型文も使う。以前の自由な生成より言い回しの範囲は狭い。既存の本人の記憶は保持する。初期状態の確認には新しいセーブを使う。

## モデルの表示

通常の目・まつげ・眉・口・髪・輪には原画の画素を使う。目を反転して左右を同じ形に描き直す方式をやめ、原画の自然な左右差を保つ。閉眼は別の作画を使い、見えるまつげの横幅を比較する。開閉の途中は二重に重ねず、開眼と閉眼を切り替える。

後ろ髪を6部品に分けて顔の後ろへ置き、前髪と独立眉を分ける。胴500・首590・顔600・耳610・襟650・口の開口801・前髪900・開眼910・閉眼920・眉950。首が顔や襟の前へ出ない順序にする。通常時は開口用の口を隠して原画の口を表示し、発声時だけ口を縦に開く。テクスチャの未使用部分が顔へ混ざらない配置にする。

描画比較と検証方法は [モデル比較](avatar-materials/esi02-face-comparison/README.md)。実機のGPU・音声・表示の確認は [Windows実機確認](ESI-02-Windows実機確認.md)。

## ZIPで導入済みの更新

1. ESI-02を終了する。
2. 新しいGitHubのZIPを別の場所へ展開する。
3. その中の `src`・`scripts`・`docs` を、現在使っているESI-02フォルダーへ上書きする。
4. 現在の `models`・`data`・`.venv-esi02` は保持し、通常の起動用ファイルで起動する。

AIデータの再ダウンロードは不要。GitHubのZIPには `.git` がないため、ZIP導入したフォルダーで `git pull` は使えない。外部で起動したllamaが残っている場合、この更新の起動コマンドは外部プロセスに適用されない。そのプロセスを自分で終了してから通常起動する。
