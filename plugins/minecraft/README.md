# ESI Minecraft Bridge 0.4.6

利用者向けの導入と試し方は [Minecraft連携の手順](../../docs/ESI-04-Minecraft連携.md) を参照してください。`release/esi-minecraft-bridge-0.4.6.jar` が配布用MODです。テスト用のMODやMinecraft本体は同梱しません。

## ビルド

JDK 21を用意し、このディレクトリーで実行します。

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTest
```

Linux/macOSでは `./gradlew build`、`./gradlew runGameTest`。Gradle 9.2.1、Loom 1.14.10、Minecraft 1.21.11の公式マッピング、Fabric API 0.141.6+1.21.11、Carpet 1.4.194を固定しています。`build`にも自動ゲームテストを含めています。配布するのは `build/libs/esi-minecraft-bridge-0.4.6.jar` です。

`runGameTest` は専用のテストワールドを起動します。製品にはない試験用の床・道具・食べ物をテストソースでのみ作り、通常の物理移動、採掘時間、道具の摩耗、拾得、食事時間、アイテム消費とゲージ回復、停止、再接続の保存、見えていない対象の拒否を確認します。未解放レシピの拒否、2×2/作業台3×3のクラフト、材料消費、所持品が満杯の時の材料返却、収納の預け入れ・取り出し・停止時の閉鎖も確認します。0.4.6では浅い穴からの通常の歩行・ジャンプ、接続者本人の会話受付、自己出力の除外、返答の重複配送も検査します。

実際のPythonクライアントと言語モデルも使う試験では、`ESI_MC_E2E` に空の試験用ディレクトリーを指定して `runGameTest` を起動し、同じ変数とローカルLLMを指定して以下を実行します。

```bash
ESI_MC_E2E=/path/to/private-test-folder pytest -q tests/test_esi04_minecraft_integration.py
```

この試験用フォルダーには一時的な接続コードが作られるため公開しません。テスト用HTTP待機は通常の `runGameTest` では即終了します。

クラフトの判断と実際の材料消費を単独で確認する場合は、Gradleとpytestの両プロセスに `ESI_MC_CRAFT_ONLY=1` も指定します。試験用の満腹度を20にし、クラフトの目標・利用者からの材料の教え・解放済みレシピを渡します。予測が外れても、実際の材料減少と完成品増加を正しく記録することを確認します。GameTestのヒープは1 GiBに制限し、小さな検証環境での連続試験を安定させています。

行動指示のない生活を確認する場合は、両プロセスに別の `ESI_MC_LIFE_E2E=/path/to/private-life-folder` を指定し、GameTestと `pytest -q tests/test_esi04_life_integration.py` を起動します。空の希望欄から実モデルが目的と一操作を選び、12回以上の判断、取得・食事・複数の場所への移動、本体とゲーム内からの会話、会話後の継続、明示停止、保存・再起動を確認します。音声の出力先だけを文字用へ置き換え、判断・通信・操作結果・ゲームの物理処理は実物を使います。試験フォルダーには接続コードと会話記録があるため公開しません。CPU推論では長時間かかる試験です。

## プラグインと通信

ESIの同梱定義は `src/esi04/resources/plugins/minecraft.json` です。外部のJSON定義は、ESIのセーブと同じフォルダーの `plugins` に追加されます。任意のPythonをインポートする方式ではなく、宣言した知識・操作・身体条件と、別プロセスの接続先を組み合わせる方式です。定義だけを追加しても、新しいゲームの接続プログラムは自動生成されません。

API v1は現在のMinecraft用観察・行動スキーマに対応します。0.4.6の拡張フィールドを読むため、ESI本体とBridge MODは一緒に更新します。新しい種類の環境を足す場合は、その接続先と観察・身体・行動のアダプターを追加します。Python側のスキーマ・接続処理は `esi04/plugins.py`、環境切り替えは `plugin_session.py`、非同期処理は `plugin_runtime.py`、Minecraftの基本知識と選択可能な行動は `minecraft.py`、出典付きの経験・小目標・場所は `environment_learning.py`、継続する目的は `environment_life.py`、同じ生活に基づく返答は `environment_dialogue.py` に分離しています。

MODは `127.0.0.1:8766–8775` にだけ待ち受け、利用者の `/esi link` で発行したBearerコードと、接続ごとの `X-ESI-Lease` を照合します。WebブラウザーのOrigin付き要求を拒否します。任意コマンド・シェルの実行口は設けていません。

| API | 内容 |
| --- | --- |
| POST `/v1/connect` | protocol・plugin_id・character_idを照合して参加し、leaseを発行 |
| GET `/v1/state` | 自分の身体・所持品・見える周囲・直前の操作結果、解放済みレシピ、実際に開いた収納、昼夜、接続者本人からの呼びかけ |
| POST `/v1/action` | 観察IDと操作IDに結び付いた1回の操作 |
| POST `/v1/chat` | 会話IDで重複を防いで接続者本人へ返答し、配送確認を返す |
| POST `/v1/stop` | 現在の移動・使用・採掘を解除 |
| POST `/v1/disconnect` | 操作を止めて通常の退出・保存 |

観察はブロック半径8・視線遮蔽で制限します。隠れた鉱石、シード、他人の所持品は渡しません。現在の可視リストは最大40ブロック・12エンティティ・20足場、同じブロック種は最大8です。足場は全方向と近い一段の出口を含めます。言語モデルへの入力はさらに小さく選びます。決定が遅い場合も、実行前に最新の観察で同じワールド・対象・所持品を確認します。

身体の操作はMinecraftのサーバースレッドに渡します。移動はCarpetの通常入力、近距離の経路は見える足場からのA*、採掘・食事・設置は通常のATTACK/USEです。初参加以外の位置移動にはテレポートを使いません。再接続の位置・ディメンションは保存データから復元します。

クラフトは `ServerRecipeBook` の既知レシピのうち、通常の `CraftingRecipe` だけを対象にし、vanillaのレシピ配置と結果スロットから取得します。材料の生成・無償配布・全レシピ解放は行いません。収納は実際に使用操作で開いた `ChestMenu`（樽を含む）/ `HopperMenu` / `ShulkerBoxMenu` のスロットだけを通常のQUICK_MOVEで操作します。観察したメニューID、スロットの品名、現在の距離と `stillValid` を再確認します。

操作結果の `evidence.before/after` は、操作の直前と終了時にサーバーが取得した自分の状態です。ESIで発行した操作IDと観察IDに一致する時だけ学習へ使います。目標の確認条件と、実際に起きた変化を分けます。ブロック変化・取得・食事・移動の事実から、その操作の因果関係が一般に成立するとは断定しません。人格への正の報酬は取得・食事の確認と実位置から確認した初訪問、負の報酬は実際の体力減少から与えます。既知の場所の巡回、視線の反復、生成した計画・説明には学習の報酬を与えません。

保存は場所192セル、条件別試行96件、最近の経験64件、操作結果512件を上限にします。ワールド・ディメンションを区別し、過去の場所を現在の観察として扱いません。LLMには最大6種類のブロック・2種類のエンティティ・4足場、所持品10スロット・レシピ5件・収納5スロットを選んで渡します。入力上限に達した場合は過去の参照を減らし、現在の観察と選択メニューを保持します。画面の手動操作一覧では現在の全観察を選べます。
